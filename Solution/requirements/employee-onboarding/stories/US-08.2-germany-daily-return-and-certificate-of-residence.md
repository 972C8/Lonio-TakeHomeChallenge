# US-08.2 – Germany: daily return and certificate of residence

Part of [Employee onboarding questionnaire](../feature.md), section [6. Source tax: residence abroad and cross-border questions](../feature.md#SEC-08-cross-border-residence).

**As** source tax office, **I want** employees living in Germany to state whether they return home daily and, if so, whether they have a certificate of residence, **so that** the cross-border tariff is applied only when the calculator's conditions are met and the normal tariff otherwise

Priority **P1** – The answer changes the tariff letter (e.g. N1Y instead of C1Y); Lonio owns the tariff code (D-001) and HR could never remember the German forms (F-hr_transcript-8595fb). · Status: **decision** · Sources: F-zh_source_tax_calculator-69edd5, F-zh_source_tax_calculator-64ac42, F-zh_source_tax_calculator-31d762, F-zh_source_tax_calculator-687e8b, F-zh_source_tax_calculator-823151, F-zh_source_tax_calculator-5f6820, F-zh_source_tax_calculator-993db3, F-hr_transcript-8595fb, D-001, D-034, D-035, D-037, D-047, D-051

Covers (details in [the section](../feature.md#SEC-08-cross-border-residence) and [information.md](../information.md)): Daily return to Germany, Certificate of residence, Cross-border (Grenzgänger) tariff applies

## Acceptance criteria

- **AC-08.2.1 Daily return to Germany is asked of Germany residents**
  - **Given** the employee lives in Germany
  - **When** the employee reaches step 5 Cross-border commuting
  - **Then** the employee is asked whether they return daily to their main residence in Germany, as they expect it for the year; the answer is required and is 'yes' or 'no'. It is recorded for the source tax tariff code. Employees living elsewhere are not asked.
  - _Sources: F-zh_source_tax_calculator-69edd5, F-zh_source_tax_calculator-64ac42, F-zh_source_tax_calculator-31d762, D-035, D-047_

  | Example | Country of residence (home address country) | → | Daily return to Germany | Checked |
  |---|---|---|---|---|
  | Lives in Germany (illustrative) | Germany | → | required | ✅ |
  | Lives in Liechtenstein (illustrative) | Liechtenstein | → | not asked | ✅ |

- **AC-08.2.2 Certificate of residence is asked only with daily return**
  - **Given** the employee lives in Germany
  - **When** the employee answers that they return daily
  - **Then** the employee is asked whether they have a certificate of residence for HR; the answer is required and is 'yes', 'no' or 'not yet'. A new hire often has no certificate yet, so 'not yet' is valid. Nothing is uploaded: the document goes to HR outside Lonio. Employees who do not return daily are not asked.
  - _Sources: F-zh_source_tax_calculator-687e8b, F-zh_source_tax_calculator-823151, F-zh_source_tax_calculator-5f6820, D-035_

  | Example | Country of residence (home address country) | Daily return to Germany | → | Certificate of residence | Checked |
  |---|---|---|---|---|---|
  | Germany, daily return (illustrative) | Germany | yes | → | required | ✅ |
  | Germany, no daily return (illustrative) | Germany | no | → | not asked | ✅ |

- **AC-08.2.3 Cross-border tariff with daily return and certificate**
  - **Given** the employee lives in Germany and returns daily
  - **When** Lonio decides between the cross-border and the normal tariff
  - **Then** with a certificate of residence the cross-border tariff applies; with 'no' or 'not yet' the normal tariff applies
  - _Sources: F-zh_source_tax_calculator-993db3, D-035, D-001_

  | Example | Country of residence (home address country) | Daily return to Germany | Certificate of residence | → | Cross-border (Grenzgänger) tariff applies | Checked |
  |---|---|---|---|---|---|---|
  | Calculator example daily return + certificate -> N1Y (zh_source_tax_calculator/F-zh_source_tax_calculator-993db3) | Germany | yes | yes | → | yes | ✅ |
  | Calculator example daily return, no certificate -> C1Y (zh_source_tax_calculator/F-zh_source_tax_calculator-993db3) | Germany | yes | no | → | no | ✅ |
  | Certificate not yet available (illustrative) | Germany | yes | not yet | → | no | ✅ |

- **AC-08.2.4 Cross-border letter in the tariff code**
  - **Given** the cross-border tariff applies to an employee living in Germany
  - **When** Lonio computes the tariff code
  - **Then** the base tariff letter is replaced by its cross-border letter (A becomes L, B becomes M, C becomes N, H becomes P), while the child digit and church-tax suffix stay the same; for example the calculator gives N1Y with a certificate and C1Y without it, for the same person
  - _Sources: F-zh_source_tax_calculator-993db3, D-001, D-051_
- **AC-08.2.5 Certificate handed in later**
  - **Given** the employee answered 'not yet' to the certificate of residence and has submitted the questionnaire
  - **When** the employee later hands the certificate to HR
  - **Then** the employee cannot change the answer in Lonio, because the questionnaire is read-only after submission; HR records the change (specified in the later HR-side spec), and the tariff code is always derived again from the latest answers
  - _Sources: D-035, D-037, D-034_

## Evidence
- **D-001** (product decision (Product owner)): Lonio computes the full Zurich source tax tariff code (tariff letter including the cross-border letters, child digit and church-tax suffix, e.g. "C1Y", "L0Y") for every employee subject to source tax, from the answers it collects, following the calculator's logic. HR no longer clicks through the calculator.
- **D-034** (product decision (Product owner)): Only the employee side is in scope. Who starts the onboarding and any HR screen are specified later; the spec says answers are recorded for HR, not 'available to HR'. HR-side needs from D-007 (flag) and D-033 (HR changes the date) are noted for that later spec.
- **D-035** (product decision (Product owner)): For the cross-border questions the employee states what they expect for the year (non-return days). For the certificate of residence 'not yet' is a valid answer and counts as 'no' for the tariff code. Documents go to HR outside Lonio; no upload.
- **D-037** (product decision (Product owner)): After submission the questionnaire is read-only for the employee. Any later change (a move, a marriage, a new child, a certificate of residence handed in later, a corrected nationality) is made by HR and belongs to the later HR-side spec (D-034). Every derived result (insurance start date, civil status for the fund and for source tax, subject to source tax, tariff code) is always derived again from the latest answers, as for the first working day (D-033).
- **D-047** (product decision (Product owner)): The questionnaire has exactly these steps, in this order, and feature.md, the flow rule and the stories use the same list. 1 About you (first name, last name, date of birth, first working day); 2 Home address (as on the first working day, canton only in Switzerland); 3 Nationality and C permit (only employees living in Switzerland); 4 Civil status and spouse (civil status is asked of everyone, wherever they live); 5 Cross-border commuting (Liechtenstein and Germany residents subject to source tax); 6 Source tax details (denomination, spouse gainfully employed, has children); 7 Children (one block per child); 8 Permit reminder, summary and submission. There is no separate step for the first working day. Assumption - to be verified by a domain expert; state this assumption in the user story.
- **D-051** (product decision (Product owner)): The full tariff code is one text such as 'N1Y' (letter, child digit, church-tax suffix). When no tariff code is needed the result is the text 'no tariff code'. The cross-border letter mapping follows the calculator fact in full, including G to Q where the calculator shows it. Assumption - to be verified by a domain expert; state this assumption in the user story.
