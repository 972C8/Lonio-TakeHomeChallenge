# US-06.6 – Compute and record the full source tax tariff code

Part of [Employee onboarding questionnaire](../feature.md), section [7. Source tax tariff: denomination, spouse employment and tariff code](../feature.md#SEC-06-source-tax-tariff-basics).

**As** HR, **I want** Lonio to compute the full Zurich tariff code (tariff letter, number of counted children and church-tax suffix) for every employee subject to source tax, or to state clearly why there is no code, **so that** I get the tariff code without clicking through the calculator myself, and I can see straight away which employees need no code or need my attention

Priority **P1** – This is the product decision to replace HR's manual calculator step (D-001). - **AC-06.6.3 Liechtenstein residents in principle not liable get the treaty notice instead of a code**
  - **Given** an employee living in Liechtenstein who returns home daily, or who does not return daily but expects at most 45 non-return days

  - **Then** Instead of a tariff code the result is 'in principle no source tax liability, subject to the double taxation agreement'. It is flagged for HR; how HR sees the flag is part of the later HR-side spec (D-034). The denomination, spouse employment and children questions are not asked. - **AC-06.6.5 Incomplete code after an HR change**
  - **Given** an employee subject to source tax for whom an answer the code needs is missing, for example because HR changed an answer after submission and a question now applies that the employee was never asked
  - **When** Lonio computes the tariff code
  - **Then** The result is 'incomplete - HR must complete' instead of a code until HR enters the missing answers. The questionnaire stays read-only for the employee and is not reopened. Assumption, to be verified by a domain expert (D-048, D-053).
  - _Sources: D-037, D-048, D-053_

- **AC-06.6.6 Code always follows the latest answers**
  - **Given** a submitted questionnaire whose answers HR later changes (for example a move, a marriage, a new child or a certificate of residence handed in later)
  - **When** the tariff code is looked at again
  - **Then** The code is always worked out again from the latest answers. Answers that no longer apply are discarded. No earlier code is kept.
  - _Sources: D-033, D-037, D-048_
- **AC-06.6.7 Unexplored calculator paths are checked before go-live**
  - **Given** tariff codes for paths not observed in the calculator: more than 3 counted children (for example H3N or P3N and above), the inferred per-child results, and the residence block for A, B and H
  - **When** Lonio is prepared for go-live
  - **Then** Before go-live a domain expert compares Lonio's computed codes with the calculator for these paths. This is a non-blocking go-live condition (see OQ-calculator-coverage). Where a calculator result has been observed, it wins over the general rule (assumption D-046). Special tariffs such as D (second job) are out of scope.
  - _Sources: D-009, D-044, D-046_
