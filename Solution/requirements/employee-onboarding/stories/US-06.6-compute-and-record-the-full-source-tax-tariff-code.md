# US-06.6 – Compute and record the full source tax tariff code

Part of [Employee onboarding questionnaire](../feature.md), section [6. Source tax tariff: denomination, spouse employment and tariff code](../feature.md#SEC-06-source-tax-tariff-basics).

**As** HR, **I want** Lonio to compute the full Zurich tariff code (tariff letter, child digit and church-tax suffix, e.g. C1Y or L0Y) for every employee subject to source tax and record it for me, **so that** I no longer click through the Zurich calculator by hand for each new employee

Priority **P1** – HR currently runs the calculator manually for every source-taxed employee (F-hr_transcript-34494f); replacing this step is an explicit product decision (D-001). · Status: **decision** · Sources: F-hr_transcript-34494f, F-zh_source_tax_calculator-4c53e3, F-zh_source_tax_calculator-2eab9a, F-zh_source_tax_calculator-993db3, F-zh_source_tax_calculator-fb87f1, F-zh_source_tax_calculator-cc19c7, F-zh_source_tax_calculator-86d588, D-001, D-007, D-009, D-034, D-037, D-040, D-046

## Acceptance criteria

- **AC-06.6.1 Tariff code composed from letter, child digit and suffix**
  - **Given** an employee who is subject to source tax and is not a Liechtenstein resident with daily return or at most 45 non-return days
  - **When** the employee submits the questionnaire
  - **Then** Lonio records the tariff code written as the tariff letter, followed by the child digit (the number of children who count, 0 without children, no maximum), followed by the church-tax suffix Y or N, for example C1Y or L0Y

- **AC-06.6.3 Liechtenstein residents: no tariff code or tariff code with treaty note**
  - **Given** an employee living in Liechtenstein, who has answered the daily-return and, where asked, the more-than-45-days question before any denomination, spouse or children question
  - **When** the employee submits the questionnaire
  - **Then** with daily return, or without daily return and at most 45 non-return days, no tariff code is recorded; instead 'in principle no source tax liability, subject to the double taxation agreement' is recorded and flagged for HR. - **AC-06.6.4 Tariff code always follows the latest answers**
  - **Given** a submitted questionnaire with a recorded tariff code (or no tariff code)
  - **When** HR later changes an answer it depends on, for example a marriage, a new child, a move or a certificate of residence handed in later
  - **Then** the tariff code, and whether one is needed at all, is derived again from the latest answers; the employee cannot change answers after submission. How HR makes such changes belongs to the later HR-side spec.
  - _Sources: D-037, D-034, D-035_
- **AC-06.6.5 Comparison with the calculator before go-live**
  - **Given** Lonio's tariff code computation is complete
  - **When** the feature is prepared for release
  - **Then** a domain expert compares Lonio's computed tariff codes with the Zurich calculator for the paths not explored (residence block for A/B/H, more than 3 children, H3N/P3N examples and per-child results marked inferred) before go-live; where observed calculator results exist, they win over derived ones. This is a non-blocking go-live condition (see OQ-calculator-coverage). Assumption to be verified by a domain expert (D-046).
  - _Sources: F-zh_source_tax_calculator-66732c, F-zh_source_tax_calculator-332e2a, F-zh_source_tax_calculator-4957f6, F-zh_source_tax_calculator-86d588, D-009, D-046_

## Evidence
- **D-001** (product decision (Product owner)): Lonio computes the full Zurich source tax tariff code (tariff letter including the cross-border letters, child digit and church-tax suffix, e.g. "C1Y", "L0Y") for every employee subject to source tax, from the answers it collects, following the calculator's logic. HR no longer clicks through the calculator.
- **D-007** (product decision (Product owner)): Liechtenstein residents are asked the source tax questions (HR's rule decides who is asked). The result follows the calculator - with daily return or at most 45 non-return days, Lonio shows 'in principle no source tax liability, subject to the double taxation agreement' instead of a tariff code, flagged for HR; with more than 45 non-return days, the normal tariff code. This closes OQ-liechtenstein-conflict. To be verified by a domain expert.
- **D-009** (product decision (Product owner)): Before go-live a domain expert compares Lonio's computed tariff code with the calculator for the paths not explored (residence block for A/B/H, more than 3 children, H3N/P3N). Special tariffs such as D (second job) are out of scope for onboarding. Keep OQ-calculator-coverage open as a non-blocking go-live condition.
- **D-034** (product decision (Product owner)): Only the employee side is in scope. Who starts the onboarding and any HR screen are specified later; the spec says answers are recorded for HR, not 'available to HR'. HR-side needs from D-007 (flag) and D-033 (HR changes the date) are noted for that later spec.
- **D-035** (product decision (Product owner)): For the cross-border questions the employee states what they expect for the year (non-return days). For the certificate of residence 'not yet' is a valid answer and counts as 'no' for the tariff code. Documents go to HR outside Lonio; no upload.
- **D-037** (product decision (Product owner)): After submission the questionnaire is read-only for the employee. Any later change (a move, a marriage, a new child, a certificate of residence handed in later, a corrected nationality) is made by HR and belongs to the later HR-side spec (D-034). Every derived result (insurance start date, civil status for the fund and for source tax, subject to source tax, tariff code) is always derived again from the latest answers, as for the first working day (D-033).
- **D-040** (product decision (Product owner)): For employees living in Liechtenstein, the questions on daily return and on more than 45 days abroad come before denomination, spouse and children. When the answers mean 'in principle no source tax liability', the tariff questions are skipped. When the employee stays abroad more than 45 days, the normal tariff is recorded with the note 'subject to the double taxation agreement' and flagged for HR. Assumption - to be verified by a domain expert; state this assumption in the user story.
