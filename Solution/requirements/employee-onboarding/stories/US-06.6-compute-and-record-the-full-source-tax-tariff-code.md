# US-06.6 – Compute and record the full source tax tariff code

Part of [Employee onboarding questionnaire](../feature.md), section [7. Source tax tariff: denomination, spouse employment and tariff code](../feature.md#SEC-06-source-tax-tariff-basics).

**As** HR, **I want** Lonio to compute one complete Zurich tariff code (letter, child digit and church-tax suffix, e.g. 'C1Y') for every employee subject to source tax, and a clear text result for everyone else, **so that** I no longer click through the calculator for each new employee and I can see at once who needs a tariff and which one

Priority **P1** – This removes HR's manual calculator step for every employee (D-001, F-hr_transcript-34494f). Today HR does not know up front who has to answer the source tax questions (F-hr_transcript-b84498). · Status: **decision** · Sources: F-hr_transcript-34494f, F-hr_transcript-b84498, F-zh_source_tax_calculator-4c53e3, F-zh_source_tax_calculator-86d588, F-zh_source_tax_calculator-993db3, F-zh_source_tax_calculator-fb87f1, F-zh_source_tax_calculator-cc19c7, D-001, D-007, D-009, D-034, D-037, D-040, D-048, D-051

## Acceptance criteria

- **AC-06.6.1 Employees subject to source tax get a full tariff code**
  - **Given** an employee is subject to source tax and is not a Liechtenstein resident who in principle has no source tax liability
  - **When** Lonio computes the tariff code from the latest answers
  - **Then** the result is one text made of the tariff letter (including the cross-border letter where it applies), the child digit (the number of children who count) and the church-tax suffix, for example 'C1Y', 'L0Y' or 'N1Y'. It is recorded for HR. Assumption to be verified by a domain expert (D-051): the code is this single text. Like the calculator's result, the code is not legally binding.

- **AC-06.6.2 Employees not subject to source tax get 'no tariff code'**
  - **Given** an employee who is not subject to source tax (a Swiss national, a C-permit holder, or someone exempt through a Swiss or C-permit spouse living in Switzerland)
  - **When** Lonio computes the tariff code
  - **Then** the result is the text 'no tariff code', and none of the step 6 source tax questions were asked.
  - _Sources: D-051, F-hr_transcript-b84498, F-hr_transcript-845204, F-hr_transcript-b90bd9_

- **AC-06.6.3 Liechtenstein residents: in principle no liability, or code subject to the double taxation agreement**
  - **Given** an employee living in Liechtenstein
  - **When** Lonio computes the tariff code
  - **Then** if the employee returns daily, or does not return daily and expects at most 45 non-return days, the result is the text 'in principle no source tax liability, subject to the double taxation agreement', flagged for HR, and the step 6 questions are skipped. If the employee expects more than 45 non-return days, the result is the normal tariff code (never a cross-border letter), recorded with the note 'subject to the double taxation agreement' and flagged for HR. Assumption to be verified by a domain expert (D-040, D-007). How HR handles the flag belongs to the later HR-side spec (D-034).

- **AC-06.6.4 Tariff code is always derived again from the latest answers**
  - **Given** the employee has submitted the questionnaire and HR later changes an answer (for example a marriage, a new child, a move, or a certificate of residence handed in later)
  - **When** Lonio derives the tariff code again
  - **Then** the tariff code reflects the latest answers. If the change means that questions apply that were never answered (for example the spouse employment question after a change to Married), the result is 'incomplete - HR must complete' instead of a code until HR enters the missing answers. Answers that no longer apply are discarded, as on the employee's submission. Assumption to be verified by a domain expert (D-048). How HR makes these changes belongs to the later HR-side spec (D-034, D-037).
  - _Sources: D-037, D-048, D-034, D-036_
- **AC-06.6.5 Unexplored calculator paths are checked before go-live**
  - **Given** Lonio computes tariff codes on paths that were not observed in the calculator (the residence block for A/B/H, more than 3 children, H3N/P3N, and per-child results marked as inferred)
  - **When** the feature is prepared for go-live
  - **Then** a domain expert compares Lonio's computed codes with the Zurich calculator for these paths before release (see OQ-calculator-coverage; a go-live condition that does not block this spec). Special tariffs such as D (second job) are out of scope for onboarding.
  - _Sources: D-009, D-046_
