# US-05.7 – Compute and record the source tax result for HR

Part of [Employee onboarding questionnaire](../feature.md), section [5. Source tax tariff basics and computed result](../feature.md#SEC-05-tariff-basics).

**As** HR, **I want** Lonio to compute the full Zurich tariff code (letter, child digit, church-tax suffix) or the Liechtenstein result for every employee subject to source tax and record it for HR, **so that** I get the source tax result without clicking through the calculator, for every employee whatever their residence

Priority **P1** – HR today derives every tariff code by hand in the calculator (F-hr_transcript-563a9f, F-hr_transcript-4e180e); the product decision replaces this step (D-001). · Sources: F-zh_source_tax_calculator-ecef37, F-zh_source_tax_calculator-2eab9a, F-zh_source_tax_calculator-e80d8f, F-zh_source_tax_calculator-ab4e1e, F-zh_source_tax_calculator-b7154e, F-hr_transcript-4e180e, F-hr_transcript-563a9f, D-001, D-007, D-034

## Acceptance criteria

- **AC-05.7.1 Which result applies**
  - **Given** the employee has answered all questions that apply to them
  - **When** the questionnaire is submitted
  - **Then** employees not subject to source tax get no source tax result; Liechtenstein residents who return daily or expect at most 45 non-return days get 'in principle no source tax liability, subject to the double taxation agreement' instead of a tariff code, flagged for HR; Liechtenstein residents with more than 45 non-return days get the tariff code subject to the double taxation agreement; everyone else subject to source tax (Switzerland, Germany or another country) gets the tariff code. The Zurich logic is used for everyone. The result is recorded for HR; how HR handles the flag is specified in the later HR-side spec (D-034).

- **AC-05.7.2 Tariff code = letter + child digit + church-tax suffix**
  - **Given** an employee whose result is a tariff code
  - **When** Lonio computes the code
  - **Then** the code is the tariff letter, followed by the number of counting children (0 if none), followed by Y or N from the denomination (e.g. C1Y, L0Y), as the calculator would show it. Paths not explored in the calculator are verified before go-live (see OQ-calculator-coverage).
