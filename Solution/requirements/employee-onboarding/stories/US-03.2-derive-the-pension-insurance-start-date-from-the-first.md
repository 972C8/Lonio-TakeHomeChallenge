# US-03.2 – Derive the pension insurance start date from the first working day

Part of [Employee onboarding questionnaire](../feature.md), section [3. First working day and insurance start date](../feature.md#SEC-03-employment-start).

**As** pension fund, **I want** to receive an insurance start date on the 1st of a month that is derived from the employee's first working day, **so that** the employee is registered with the correct insurance start without the employee having to know the fund's rule

Priority **P1** – The insurance start date is a required field of the pension fund registration; a wrong date caused an unfriendly letter from the fund and weeks of fixing (F-pension_portal-509cbe, F-hr_transcript-e18e66). · Sources: F-hr_transcript-1d5c07, F-hr_transcript-fdf50a, F-hr_transcript-30d25c, F-pension_portal-509cbe, F-pension_portal-dd8126, F-pension_portal-3a97ab, G-08, D-039, D-045

Covers (details in [the section](../feature.md#SEC-03-employment-start) and [information.md](../information.md)): First working day, Insurance start date

## Acceptance criteria

- **AC-03.2.1 The insurance start date is derived, not asked**
  - **Given** the employee has entered a first working day
  - **When** the questionnaire is filled in
  - **Then** the employee is not asked for an insurance start date; Lonio derives it from the first working day only and records it for the pension fund as a date DD.MM.YYYY on the 1st of a month
  - _Sources: G-08, F-pension_portal-509cbe, F-pension_portal-dd8126, F-pension_portal-3a97ab, D-039_
- **AC-03.2.2 Start on the 1st of a month: insurance starts the same day**
  - **Given** the first working day is the 1st of a month
  - **When** the insurance start date is derived
  - **Then** the insurance start date is the first working day itself
  - _Sources: F-hr_transcript-1d5c07, F-hr_transcript-fdf50a_

  | Example | First working day | → | Insurance start date | Checked |
  |---|---|---|---|---|
  | Start on 1 April (illustrative) | 01.04.2026 | → | 01.04.2026 | ✅ |
  | Contractual start on Saturday 1 August (public holiday) (illustrative) | 01.08.2026 | → | 01.08.2026 | ✅ |

- **AC-03.2.3 Start on any other day: insurance starts on the 1st of the following month**
  - **Given** the first working day is not the 1st of a month
  - **When** the insurance start date is derived
  - **Then** the insurance start date is the 1st of the month after the first working day, also across a year end
  - _Sources: F-hr_transcript-1d5c07, F-hr_transcript-30d25c_

  | Example | First working day | → | Insurance start date | Checked |
  |---|---|---|---|---|
  | Julia, start on 15 March (hr_transcript/F-hr_transcript-30d25c) | 15.03.2026 | → | 01.04.2026 | ✅ |
  | Start on the 2nd of a month (illustrative) | 02.06.2026 | → | 01.07.2026 | ✅ |
  | Start on the last day of the year (illustrative) | 31.12.2026 | → | 01.01.2027 | ✅ |

- **AC-03.2.4 Weekend or holiday does not shift the insurance start**
  - **Given** the contractual first working day falls on a weekend or public holiday
  - **When** the insurance start date is derived
  - **Then** the derivation uses the contractual date as entered, not the next day actually worked. Assumption (D-039), to be verified by a domain expert.
  - _Sources: D-039, D-045_

  | Example | First working day | → | Insurance start date | Checked |
  |---|---|---|---|---|
  | Contractual start on Sunday 15 March (illustrative) | 15.03.2026 | → | 01.04.2026 | ✅ |


## Evidence
- **D-039** (product decision (Product owner)): The first working day is the contractual start date, even when it falls on a weekend or public holiday. The insurance start date is derived from this date only. Assumption - to be verified by a domain expert; state this assumption in the user story.
- **D-045** (product decision (Product owner)): Business text (stories, acceptance criteria, notices) uses no internal snake_case ids and does not speak of 'expressions'. Any behaviour that has no cited fact or decision is stated in the story as an assumption. Assumption - to be verified by a domain expert; state this assumption in the user story.
- **F-hr_transcript-1d5c07** (hr_transcript): Consolidated rule: the insurance start date is derived from the first working day. If the first working day is the 1st of a month, insurance starts that day. Otherwise it starts on the 1st of the following month.
  - "because insurance starts on the first of the following month." — hr_transcript/T-026, Anna
  - "Unless somebody starts exactly on the first, of course, then it's just that day." — hr_transcript/T-028, Anna
- **F-hr_transcript-30d25c** (hr_transcript): First version: pension fund insurance starts on the first day of the month after the first working day (for example, first working day 15.03 gives insurance start 01.04).
  - "because insurance starts on the first of the following month. So for her that was the first of April" — hr_transcript/T-026, Anna
- **F-hr_transcript-fdf50a** (hr_transcript): Exception: if the first working day is the first day of a month, insurance starts on that same day.
  - "Unless somebody starts exactly on the first, of course, then it's just that day." — hr_transcript/T-028, Anna
- **F-pension_portal-3a97ab** (pension_portal, inferred): The portal requires an insurance start date on the 1st of a month but does not show how it relates to the employee's first working day (e.g. which 1st of a month to choose when work starts mid-month); the derivation rule is unknown.
  - "DD.MM.YYYY. Must be the 1st of a month." — 01-empty.png (pension_portal/S01-E14)
- **F-pension_portal-509cbe** (pension_portal): The pension fund registration form has a text field 'Insurance start date' in the Insurance section, marked required.
  - "Insurance start date" — 01-empty.png (pension_portal/S01-E13)
  - "Insurance" — 01-empty.png (pension_portal/S01-E12)
- **F-pension_portal-dd8126** (pension_portal): Insurance start date must be in the format DD.MM.YYYY and must be the 1st of a month.
  - "DD.MM.YYYY. Must be the 1st of a month." — 01-empty.png (pension_portal/S01-E14)
- **G-08** (product owner guidance): Prefer asking for primary facts and **deriving** values (e.g. ask the first working day, derive the insurance start date) instead of asking the employee for values they cannot know.
