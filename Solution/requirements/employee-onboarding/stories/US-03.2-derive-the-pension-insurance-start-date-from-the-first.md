# US-03.2 – Derive the pension insurance start date from the first working day

Part of [Employee onboarding questionnaire](../feature.md), section [3. First working day and insurance start date](../feature.md#SEC-03-employment-start).

**As** pension fund, **I want** the insurance start date to be derived from the first working day instead of being asked from the employee, **so that** the registration always carries a valid insurance start date on the 1st of a month that matches the employee's actual start, without the employee having to know the fund's rule

Priority **P1** – The insurance start date is a required field of the pension fund registration and must be the 1st of a month; a wrong date led to an unfriendly letter from the fund and weeks of fixing. · Sources: F-hr_transcript-1d5c07, F-pension_portal-509cbe, F-pension_portal-dd8126, G-08, D-037

Covers (details in [the section](../feature.md#SEC-03-employment-start) and [information.md](../information.md)): First working day, Insurance start date

## Acceptance criteria

- **AC-03.2.1 Insurance start date is not asked**
  - **Given** a new employee fills in the onboarding questionnaire
  - **When** the employee goes through all questions
  - **Then** the employee is never asked for an insurance start date; it is derived from the first working day
  - _Sources: G-08, F-hr_transcript-1d5c07_
- **AC-03.2.2 Start on the 1st of a month: insurance starts that day**
  - **Given** the employee's first working day is the 1st of a month
  - **When** the insurance start date is derived
  - **Then** the insurance start date is the first working day itself
  - _Sources: F-hr_transcript-1d5c07, F-pension_portal-dd8126_

  | Example | First working day | → | Insurance start date | Checked |
  |---|---|---|---|---|
  | Start on 1 March (illustrative) | 01.03.2026 | → | 01.03.2026 | ✅ |
  | Start on 1 January (illustrative) | 01.01.2027 | → | 01.01.2027 | ✅ |

- **AC-03.2.3 Start on any other day: insurance starts on the 1st of the following month**
  - **Given** the employee's first working day is not the 1st of a month
  - **When** the insurance start date is derived
  - **Then** the insurance start date is the 1st of the month following the first working day, also across a year end
  - _Sources: F-hr_transcript-1d5c07, F-pension_portal-dd8126_

  | Example | First working day | → | Insurance start date | Checked |
  |---|---|---|---|---|
  | Julia (hr_transcript/F-hr_transcript-e18e66) | 15.03.2026 | → | 01.04.2026 | ✅ |
  | Start on the 2nd of a month (illustrative) | 02.02.2026 | → | 01.03.2026 | ✅ |
  | Start in December, insurance starts next year (illustrative) | 15.12.2026 | → | 01.01.2027 | ✅ |
  | Start on the last day of a month (illustrative) | 31.08.2026 | → | 01.09.2026 | ✅ |

- **AC-03.2.4 Derived date is recorded for the pension fund**
  - **Given** the employee has submitted the questionnaire
  - **When** the answers are recorded
  - **Then** the derived insurance start date (DD.MM.YYYY, always the 1st of a month) is recorded for the pension fund registration, whose 'Insurance start date' field is required
  - _Sources: F-pension_portal-509cbe, F-pension_portal-dd8126, D-034_

## Evidence
- **D-034** (product decision (Product owner)): Only the employee side is in scope. Who starts the onboarding and any HR screen are specified later; the spec says answers are recorded for HR, not 'available to HR'. HR-side needs from D-007 (flag) and D-033 (HR changes the date) are noted for that later spec.
- **D-037** (product decision (Product owner)): After submission the questionnaire is read-only for the employee. Any later change (a move, a marriage, a new child, a certificate of residence handed in later, a corrected nationality) is made by HR and belongs to the later HR-side spec (D-034). Every derived result (insurance start date, civil status for the fund and for source tax, subject to source tax, tariff code) is always derived again from the latest answers, as for the first working day (D-033).
- **F-hr_transcript-1d5c07** (hr_transcript): Consolidated rule: the insurance start date is derived from the first working day. If the first working day is the 1st of a month, insurance starts that day. Otherwise it starts on the 1st of the following month.
  - "because insurance starts on the first of the following month." — hr_transcript/T-026, Anna
  - "Unless somebody starts exactly on the first, of course, then it's just that day." — hr_transcript/T-028, Anna
- **F-pension_portal-509cbe** (pension_portal): The pension fund registration form has a text field 'Insurance start date' in the Insurance section, marked required.
  - "Insurance start date" — 01-empty.png (pension_portal/S01-E13)
  - "Insurance" — 01-empty.png (pension_portal/S01-E12)
- **F-pension_portal-dd8126** (pension_portal): Insurance start date must be in the format DD.MM.YYYY and must be the 1st of a month.
  - "DD.MM.YYYY. Must be the 1st of a month." — 01-empty.png (pension_portal/S01-E14)
- **G-08** (product owner guidance): Prefer asking for primary facts and **deriving** values (e.g. ask the first working day, derive the insurance start date) instead of asking the employee for values they cannot know.
