# US-02.2 – Insurance start date derived from the first working day

Part of [Employee onboarding questionnaire](../feature.md), section [2. First working day and insurance start date](../feature.md#SEC-02-start-date-insurance).

**As** pension fund, **I want** the insurance start date to be derived from the latest first working day and always to fall on the 1st of a month, **so that** the employee is insured from the correct date and the fund is not given a wrong start date after the first working day has moved

Priority **P1** – The fund requires an insurance start date on the 1st of a month; a start date that did not follow a moved first working day (Julia) led to a wrong registration and weeks of fixing. · Sources: F-hr_transcript-1d5c07, F-hr_transcript-30d25c, F-hr_transcript-fdf50a, F-hr_transcript-d7a23b, F-pension_portal-509cbe, F-pension_portal-dd8126, F-pension_portal-3a97ab, G-08, D-033

Covers (details in [the section](../feature.md#SEC-02-start-date-insurance) and [information.md](../information.md)): First working day, Insurance start date

## Acceptance criteria

- **AC-02.2.1 Employee is not asked for the insurance start date**
  - **Given** a new employee is filling in the questionnaire
  - **When** they go through all steps
  - **Then** they are never asked for an insurance start date; Lonio derives it from the first working day
  - _Sources: G-08, F-hr_transcript-1d5c07_
- **AC-02.2.2 First working day on the 1st of a month**
  - **Given** the first working day is the 1st of a month
  - **When** Lonio derives the insurance start date
  - **Then** insurance starts on the first working day itself
  - _Sources: F-hr_transcript-fdf50a, F-hr_transcript-1d5c07_

  | Example | First working day | → | Insurance start date | Checked |
  |---|---|---|---|---|
  | Start on the 1st of a month (illustrative) | 01.05.2026 | → | 01.05.2026 | ✅ |
  | Start on 1 January (illustrative) | 01.01.2027 | → | 01.01.2027 | ✅ |

- **AC-02.2.3 First working day on any other day**
  - **Given** the first working day is any day other than the 1st of a month
  - **When** Lonio derives the insurance start date
  - **Then** insurance starts on the 1st of the following month, also across a year end
  - _Sources: F-hr_transcript-30d25c, F-hr_transcript-1d5c07_

  | Example | First working day | → | Insurance start date | Checked |
  |---|---|---|---|---|
  | Julia (hr_transcript/F-hr_transcript-30d25c) - 15 March gives 1 April | 15.03.2026 | → | 01.04.2026 | ✅ |
  | Start on the 2nd of a month (illustrative) | 02.06.2026 | → | 01.07.2026 | ✅ |
  | Start at the end of the year (illustrative) | 31.12.2026 | → | 01.01.2027 | ✅ |

- **AC-02.2.4 Insurance start date follows every change of the first working day**
  - **Given** an insurance start date has been derived from a first working day
  - **When** the first working day changes, whether by the employee before submission or by HR after submission
  - **Then** the insurance start date is derived again from the latest first working day; a start date based on an earlier first working day never remains
  - _Sources: F-hr_transcript-d7a23b, F-hr_transcript-1d5c07, D-033_

  | Example | First working day | → | Insurance start date | Checked |
  |---|---|---|---|---|
  | Julia (hr_transcript/F-hr_transcript-d7a23b) - start moved to 15 March | 15.03.2026 | → | 01.04.2026 | ✅ |

- **AC-02.2.5 Insurance start date is recorded for the pension fund**
  - **Given** the questionnaire has been submitted
  - **When** the insurance start date has been derived
  - **Then** it is recorded for the pension fund's required 'Insurance start date' as DD.MM.YYYY and always falls on the 1st of a month
  - _Sources: F-pension_portal-509cbe, F-pension_portal-dd8126, D-034_

## Evidence
- **D-033** (product decision (Product owner)): The employee enters the first working day. After submission only HR can change it; the latest date always counts and no history of earlier dates is kept.
- **D-034** (product decision (Product owner)): Only the employee side is in scope. Who starts the onboarding and any HR screen are specified later; the spec says answers are recorded for HR, not 'available to HR'. HR-side needs from D-007 (flag) and D-033 (HR changes the date) are noted for that later spec.
- **F-hr_transcript-1d5c07** (hr_transcript, inferred): Consolidated: insurance start date is derived from the (latest confirmed) first working day: if it is the 1st of a month, insurance starts that day; otherwise on the 1st of the following month.
  - "because insurance starts on the first of the following month." — hr_transcript/T-026, Anna
  - "Unless somebody starts exactly on the first, of course, then it's just that day." — hr_transcript/T-028, Anna
- **F-hr_transcript-30d25c** (hr_transcript): Pension fund insurance starts on the first of the month following the first working day (e.g. first working day 15 March → insurance start 1 April).
  - "because insurance starts on the first of the following month. So for her that was the first of April" — hr_transcript/T-026, Anna
- **F-hr_transcript-d7a23b** (hr_transcript): Incident: Julia moved her first working day to 15 March, HR did not update it, the fund had a wrong insurance start date, leading to an unfriendly letter and weeks of fixing. This implies the insurance start date must follow changes to the first working day.
  - "She moved her first working day to the 15th of March, and I didn't update it." — hr_transcript/T-026, Anna
  - "It took weeks to fix." — hr_transcript/T-028, Anna
- **F-hr_transcript-fdf50a** (hr_transcript): Exception: if the first working day is exactly the first of a month, insurance starts on that day.
  - "Unless somebody starts exactly on the first, of course, then it's just that day." — hr_transcript/T-028, Anna
- **F-pension_portal-3a97ab** (pension_portal, inferred): The portal requires an insurance start date on the 1st of a month but does not say how it relates to the employee's first working day (e.g. which 1st of a month to use when work starts mid-month).
  - "DD.MM.YYYY. Must be the 1st of a month." — 01-empty.png (pension_portal/S01-E14)
- **F-pension_portal-509cbe** (pension_portal): The pension fund registration form has a required 'Insurance start date' field (in the Insurance section).
  - "Insurance start date" — 01-empty.png (pension_portal/S01-E13)
  - "Insurance" — 01-empty.png (pension_portal/S01-E12)
- **F-pension_portal-dd8126** (pension_portal): The insurance start date is entered as DD.MM.YYYY and must be the 1st of a month.
  - "DD.MM.YYYY. Must be the 1st of a month." — 01-empty.png (pension_portal/S01-E14)
- **G-08** (product owner guidance): Prefer asking for primary facts and **deriving** values (e.g. ask the first working day, derive the insurance start date) instead of asking the employee for values they cannot know.
