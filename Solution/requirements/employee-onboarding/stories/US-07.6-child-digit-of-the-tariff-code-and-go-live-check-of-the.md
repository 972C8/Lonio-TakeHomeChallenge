# US-07.6 – Child digit of the tariff code and go-live check of the child paths

Part of [Employee onboarding questionnaire](../feature.md), section [7. Source tax tariff: children](../feature.md#SEC-07-source-tax-children).

**As** HR, **I want** Lonio to turn the per-child results into the child digit of the tariff code and to signal when a child makes the tariff H, **so that** I no longer click through the Zurich calculator for each child, and the computed tariff code is trusted only after the unexplored child paths have been checked

Priority **P1** – HR's manual calculator step is replaced by the computed tariff code (D-001); a wrong digit means wrong source tax deductions, so the go-live check is a release condition (D-009). · Status: **inferred** · Sources: F-zh_source_tax_calculator-4c53e3, F-zh_source_tax_calculator-300c72, F-zh_source_tax_calculator-abe889, F-zh_source_tax_calculator-4957f6, F-zh_source_tax_calculator-332e2a, F-hr_transcript-34494f, D-001, D-009, D-037, D-044, D-046

Covers (details in [the section](../feature.md#SEC-07-source-tax-children) and [information.md](../information.md)): Child digit, Per-child result

## Acceptance criteria

- **AC-07.6.1 Child digit is the number of counted children**
  - **Given** the employee needs a tariff code
  - **When** Lonio derives the child digit
  - **Then** each child whose result is 'counts' or 'counts with H' adds 1 and each child whose result is 'does not count' adds 0; the child digit is the total over all children (for example three counted children give C3Y for a married employee whose spouse works), and 0 if the employee has no children. Assumption - to be verified by a domain expert: there is no maximum number of children (D-044); more than 3 children is part of the go-live check (D-009).
  - _Sources: F-zh_source_tax_calculator-4c53e3, F-zh_source_tax_calculator-abe889, F-zh_source_tax_calculator-4957f6, D-044, D-009_

  | Example | Country (of residence) | Civil status | Has children | Child: minor or adult in first education | Child lives in the same household | Child: parental custody | → | Per-child result | Child digit | Checked |
  |---|---|---|---|---|---|---|---|---|---|---|
  | Child that counts adds 1 (illustrative) | Germany | Married | yes | Minor | yes | Sole custody | → | counts | 1 | ✅ |
  | Child counted with H adds 1 (illustrative) | Germany | Single | yes | Minor | yes | Sole custody | → | counts with H | 1 | ✅ |
  | Child that does not count adds 0 (illustrative) | Germany | Single | yes | Neither | – | – | → | does not count | 0 | ✅ |
  | No children gives 0 (illustrative) | Germany | Married | no | – | – | – | → | – | 0 | ✅ |

- **AC-07.6.2 A child counted with H makes the tariff H**
  - **Given** a single, divorced, separated or widowed employee has at least one child whose result is 'counts with H'
  - **When** Lonio derives the tariff code
  - **Then** the tariff letter is H and the child digit still counts every counted child (for example one child that counts and one that counts with H give H2). Married employees and registered partners never get 'counts with H'. The tariff letter itself is set by the tariff letter rule of the source tax tariff section.
  - _Sources: F-zh_source_tax_calculator-300c72, D-001, D-003_
- **AC-07.6.3 Observed calculator rows win; inferred rows are checked before go-live**
  - **Given** a per-child result that rests on a case not observed in the calculator (marked inferred in the per-child stories), more than 3 children, or a combination of child, residence, denomination and civil status not explored
  - **When** Lonio is prepared for go-live
  - **Then** a domain expert compares Lonio's computed tariff code with the Zurich calculator for these cases before release; where an observed calculator result exists it decides the per-child result. This is a non-blocking go-live condition (see OQ-calculator-coverage). Assumption - to be verified by a domain expert (D-046).
  - _Sources: F-zh_source_tax_calculator-332e2a, F-zh_source_tax_calculator-4957f6, D-009, D-046_
- **AC-07.6.4 Results follow the latest answers**
  - **Given** the questionnaire has been submitted and a child answer is later changed by HR (for example a new child)
  - **When** Lonio derives the per-child results and the child digit
  - **Then** they are always derived again from the latest answers; the per-child results and the child digit are recorded for HR as part of the tariff code.
  - _Sources: D-037, D-034, D-001_
_Trace check: partial – AC-07.6.2's claim that married employees and registered partners never get 'counts with H' is not stated in the cited facts, which only describe H for single, divorced, separated or widowed persons._


## Evidence
- **D-001** (product decision (Product owner)): Lonio computes the full Zurich source tax tariff code (tariff letter including the cross-border letters, child digit and church-tax suffix, e.g. "C1Y", "L0Y") for every employee subject to source tax, from the answers it collects, following the calculator's logic. HR no longer clicks through the calculator.
- **D-003** (product decision (Product owner)): Civil status offers Single, Married, Divorced, Widowed, Registered partnership and Separated. For source tax, registered partnership counts as married (including the spouse exemption) and separated counts as single, as in the calculator. For the pension fund, registered partnership is entered as Married with the partner's date of birth, and separated as Married. This closes OQ-civil-status-partnership. Assumption - to be verified by a domain expert; state this assumption in the user story.
- **D-009** (product decision (Product owner)): Before go-live a domain expert compares Lonio's computed tariff code with the calculator for the paths not explored (residence block for A/B/H, more than 3 children, H3N/P3N). Special tariffs such as D (second job) are out of scope for onboarding. Keep OQ-calculator-coverage open as a non-blocking go-live condition.
- **D-034** (product decision (Product owner)): Only the employee side is in scope. Who starts the onboarding and any HR screen are specified later; the spec says answers are recorded for HR, not 'available to HR'. HR-side needs from D-007 (flag) and D-033 (HR changes the date) are noted for that later spec.
- **D-037** (product decision (Product owner)): After submission the questionnaire is read-only for the employee. Any later change (a move, a marriage, a new child, a certificate of residence handed in later, a corrected nationality) is made by HR and belongs to the later HR-side spec (D-034). Every derived result (insurance start date, civil status for the fund and for source tax, subject to source tax, tariff code) is always derived again from the latest answers, as for the first working day (D-033).
- **D-044** (product decision (Product owner)): There is no maximum number of children. A child's age is judged on the first working day. Assumption - to be verified by a domain expert; state this assumption in the user story.
- **D-046** (product decision (Product owner)): For the per-child source tax result, observed calculator table rows win over the derived expression. Inferred rows stay under the D-009 go-live check. Assumption - to be verified by a domain expert; state this assumption in the user story.
