# US-07.6 – Child digit of the tariff code and go-live check of the child paths

Part of [Employee onboarding questionnaire](../feature.md), section [8. Source tax tariff: children](../feature.md#SEC-07-source-tax-children).

**As** HR, **I want** Lonio to set the child digit of the source tax tariff code to the number of children who count, and to have the child paths not yet observed in the calculator checked before go-live, **so that** the recorded tariff code (e.g. 'C3Y') matches the calculator without HR clicking through it

Priority **P1** – The child digit is part of every tariff code Lonio computes in place of HR (D-001); unverified paths must be checked before release (D-009). · Status: **decision** · Sources: F-zh_source_tax_calculator-4c53e3, F-zh_source_tax_calculator-abe889, F-zh_source_tax_calculator-300c72, F-zh_source_tax_calculator-fd9a15, D-001, D-009, D-044, D-046, D-051, D-037

Covers (details in [the section](../feature.md#SEC-07-source-tax-children) and [information.md](../information.md)): Child digit of the tariff code, Per-child source tax result

## Acceptance criteria

- **AC-07.6.1 Each counted child adds one to the child digit**
  - **Given** The employee is subject to source tax and has completed the child blocks
  - **When** the tariff code is derived
  - **Then** Each child whose result is 'counted' or 'counted with H' adds one to the child digit; a child that is not counted adds nothing. With three counted children the digit is 3 (e.g. 'C3Y'). Without children the digit is 0. There is no maximum number of children (assumption D-044, to be verified by a domain expert). The digit is always derived again from the latest answers.
  - _Sources: F-zh_source_tax_calculator-4c53e3, F-zh_source_tax_calculator-abe889, D-044, D-037, D-051_

  | Example | Country of residence (country of the home address) | Civil status | Has biological or adopted children | Child: minor or adult in first education | Child lives in the same household | Child: parental custody | Child: shared custody (child not in household, married) | → | Per-child source tax result | Child digit of the tariff code | Checked |
  |---|---|---|---|---|---|---|---|---|---|---|---|
  | Counted child adds one (married, sole custody) (illustrative) | Germany | Married | yes | Minor | yes | Sole custody | – | → | counted | yes | ✅ |
  | Child counted with H adds one (single, sole custody) (illustrative) | Germany | Single | yes | Minor | yes | Sole custody | – | → | counted with H | yes | ✅ |
  | Child neither minor nor in first education adds nothing (illustrative) | Germany | Married | yes | Neither | – | – | – | → | not counted | no | ✅ |
  | Child not counted adds nothing (married, no shared custody) (illustrative) | Germany | Married | yes | Minor | no | – | no | → | not counted | no | ✅ |

- **AC-07.6.2 Go-live check of the child paths**
  - **Given** Lonio derives per-child results and the child digit
  - **When** the feature is prepared for go-live
  - **Then** A domain expert compares Lonio's results with the Zurich calculator for the per-child rows marked inferred and for more than 3 children (see OQ-calculator-coverage, a non-blocking go-live condition). Until then, observed calculator runs win over the derived logic (assumption D-046, to be verified by a domain expert).
  - _Sources: D-009, D-046_

## Evidence
- **D-001** (product decision (Product owner)): Lonio computes the full Zurich source tax tariff code (tariff letter including the cross-border letters, child digit and church-tax suffix, e.g. "C1Y", "L0Y") for every employee subject to source tax, from the answers it collects, following the calculator's logic. HR no longer clicks through the calculator.
- **D-009** (product decision (Product owner)): Before go-live a domain expert compares Lonio's computed tariff code with the calculator for the paths not explored (residence block for A/B/H, more than 3 children, H3N/P3N). Special tariffs such as D (second job) are out of scope for onboarding. Keep OQ-calculator-coverage open as a non-blocking go-live condition.
- **D-037** (product decision (Product owner)): After submission the questionnaire is read-only for the employee. Any later change (a move, a marriage, a new child, a certificate of residence handed in later, a corrected nationality) is made by HR and belongs to the later HR-side spec (D-034). Every derived result (insurance start date, civil status for the fund and for source tax, subject to source tax, tariff code) is always derived again from the latest answers, as for the first working day (D-033).
- **D-044** (product decision (Product owner)): There is no maximum number of children. A child's age is judged on the first working day. Assumption - to be verified by a domain expert; state this assumption in the user story.
- **D-046** (product decision (Product owner)): For the per-child source tax result, observed calculator table rows win over the derived expression. Inferred rows stay under the D-009 go-live check. Assumption - to be verified by a domain expert; state this assumption in the user story.
- **D-051** (product decision (Product owner)): The full tariff code is one text such as 'N1Y' (letter, child digit, church-tax suffix). When no tariff code is needed the result is the text 'no tariff code'. The cross-border letter mapping follows the calculator fact in full, including G to Q where the calculator shows it. Assumption - to be verified by a domain expert; state this assumption in the user story.
